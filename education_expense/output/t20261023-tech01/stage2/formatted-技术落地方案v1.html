一、方案定位与技术主线

1.1 一句话定位

在不动既有系统、不改人工审批链的前提下，旁路搭建一条"抽取 → 归并 → 起草"的 AI 流水线，把教师手工搬运的约 10 小时/月（f12）压掉，把"只有结论没有依据"的反馈补上结构化事实；所有判定权、打分权、签核权仍留在 5 道人工闸门内。

本方案只回答"技术怎么做、边界在哪、怎么验收"。凡访谈未核实的技术条件，均标注为【待核实】并给出不依赖该条件也能运行的降级路径，不作推断性设计。

1.2 三条技术铁律（不可突破）

#铁律技术含义事实依据
1模型不决定成绩评分字段在数据模型中为只读透传，AI 侧无写权限；成绩写回接口不在范围f22 · f32
2AI 只做抽取、归并与起草输出物是"事实 + 建议草案"，不含任何定性结论；建议必须挂原记录f52 · f15
3兜底优先于准确率四类触发即停自动建议并转人工，宁停不错f44

1.3 与现有系统的关系

只读旁路。接口侧仅开放只读批量导出、成绩写回不在本次范围（f32）——这既是约束也是优势：方案不需要任何写权限，集成风险与审批成本被压到最低，失败时可直接回退到现有人工流程而不留后遗症。

二、总体架构

2.1 五层架构

层组件职责技术选型建议
L1 接入层只读导出适配器 ×3（学籍 / 实习 / 课程）定时批量拉取，落地为原始快照，只读不可回写平台方导出文件 + SFTP / 开放只读接口【清单待核实】
L2 数据层主数据映射、版本与时间戳、人工修复队列三平台 ID 对齐、字段校验、缺项拦截关系库（PostgreSQL）+ 对象存储（原文快照）
L3 AI 能力层结构化抽取 / 多源归并 / 建议起草 / 要素齐备判定只做四件事，全部输出带溯源LLM 网关 + 向量检索 + 规则校验器
L4 人工闸门层教务核对、口径裁定、导师定性、专业组落课五个不可绕过的审核节点工作流引擎 + 待办队列 + 留痕审计
L5 交付层看板、双周刷新、每周复盘、快照兜底完整率与可执行率可视化BI 看板 + 定时任务

2.2 数据流（对应 To-Be 流程）

企业双周提交 ─┐ 教师回访记录 ─┼→ L3 ① 结构化抽取 → ◇要素齐备？─否→ 退回补字段（进人工修复队列） 教务补录材料 ─┘ │是 ↓ L3 ② 多源归并（附原文 + 版本） ↓ L3 ③ 建议起草（事实→建议，连原记录） ↓ L4 教师确认 → ◇异常/争议？─是→ 异常标记（结构化三字段） ↓否 L4 教务核对闸门 → ◇口径争议？─是→ 教学质量负责人裁定 ↓否 L2 批次/导师映射刷新 → L5 看板 → L4 专业组落课 → 课程动作

2.3 部署形态

私有化部署优先：数据不出校（对应 f40 访问限制、f45 不记非必要信息）。推理可走校内算力或合规云，模型调用与数据驻留分离，调用日志不含正文（仅长度与哈希）。现场终端为现有设备、不额外配设备（f13）——前端为浏览器轻应用，不要求安装。

三、AI 能力设计

3.1 能力一：结构化抽取

设计项方案
输入企业评语原文、教师回访记录、补录材料（微信 / Excel / 邮件导出）
输出 Schematask_id, task_name, evidence_text, scene, observed_at, source_ref, version
抽取策略LLM 抽取 + 规则校验器兜底：evidence_text 为空即判"缺行为实例"，不得由模型补写
禁止项不推断能力标签、不引入家庭背景 / 性别等敏感属性（f41）——提示词与输出 Schema 双重阻断
失败处理抽取置信度低或缺关键字段 → 进人工修复队列，不猜值补齐（f33）

关键设计——空值不等于没问题。历史反馈缺岗位任务字段（f31），系统必须把"字段缺失"显式建模为 MISSING 状态并在看板上单列，绝不默认填充为"正常"。

3.2 能力二：多源归并

把分散在微信、Excel、邮件中的同一业务对象合并为一条带版本链的记录。归并主键使用业务编号（学生批次 + 岗位任务 + 事件时间），而非自然语言相似度——避免"看起来像"就合并的错误。

同一主键多条来源冲突时不自动择一，标记 CONFLICT 并附全部来源，交教务核对（f15）。每次归并保留原文快照与版本号，支持"当时的资料版本"回溯（f54）。

3.3 能力三：建议起草

约束实现方式
每条建议必须挂原记录输出结构强制含 evidence_refs[]，为空则整条丢弃（f15）
不自动定性输出字段命名避开"评价 / 结论"，使用 suggested_action；定性字段由导师签核后写入（f52）
建议必须可落到课程每条建议需填 course_module 与 improvement_owner，两项为空则不得进入评审（对齐 f42 的 24/30 口径）

3.4 能力四：要素齐备判定

纯规则实现（非模型），避免"模型判断模型"的循环依赖：

齐备 := task_id 有效 ∧ evidence_text 非空 ∧ source_ref 可解析 ∧ version 存在

任一为假即判 INCOMPLETE，附带缺失字段清单，退回提交人或进修复队列。

3.5 模型选型与网关

项建议
模型中文长文本抽取能力优先；私有化可选中型开源模型微调，云侧可选商用 API
网关统一网关做路由、限流、重试与成本计量（Token 用量单列，与报价科目 07 对应）
提示词管理版本化托管，与规则版本绑定；规则更新必须走 f55 的复测后才生效
禁止禁止把学生个人记录发往未授权的境外服务；禁止在提示词中拼接完整个人信息

四、数据与主数据方案

4.1 三平台 ID 映射

学籍、实习、课程平台各用一套 ID，学生与实习批次尚无统一映射（f30）。

步骤做法
1 盘点明确三平台 ID 字段、导出频率、责任人——本项为【待核实】前置任务
2 建主编号以"学生主编号 + 实习批次号"为业务主键，三平台 ID 作为别名表
3 校验主编号、事件时间、来源、版本四要素校验，缺项进人工修复队列（f33）
4 换岗刷新换岗 / 延期事件触发即时重算导师关联，不等双周刷新（解决 f11）

4.2 刷新与时效

试点数据每两周刷新一次，原文按版本同步（f34）。超过一个周期的结果标注 STALE（待刷新），采用版本号 + 时间戳双标记，不靠人眼看日期；历史快照不得伪装成当前状态——看板必须区分"当前 / 待刷新 / 历史快照"三态。

4.3 接口失败兜底

接口失败时继续走原人工流程，保留只读快照与时间戳；恢复后按业务编号去重补齐，不重复创建同一待办（f35）。技术实现：幂等键为"业务编号 + 事件时间"，写入前查重；失败队列积压时看板亮红，但不阻塞人工流程。

4.4 弱网与待补状态

现场需要保留待补信息与最后同步时间，记录不能丢、也不能被当成已完成（f13）。前端本地暂存（IndexedDB），断网可填；每条记录带 pending_fields[] 与 last_synced_at；复核视图必须能区分"没反馈"与"没同步上来"，这两个状态在看板上使用不同颜色与图标。

五、权限、隐私与可追溯

5.1 四级可见性矩阵

角色可见范围粒度依据
企业实习导师本企业学生的记录个体f40（不得向其他企业公开）
实习指导教师本人带教学生个体 + 原文f12 · f15
专业组 / 教学质量负责人去标识化聚合结论聚合（≥5 人才展示）f40 · f42
教务管理员全量（含个体链路）个体 + 版本 + 日志f15 · f24

【待核实】权限分级能做到什么程度需系统侧确认；上表为本方案的目标矩阵，实施前需与信息侧对齐落地方式。

5.2 敏感属性阻断（三层）

输入侧：抽取前过滤家庭背景、性别等字段，不进入模型上下文（f41）。提示词侧：显式禁止据此解释能力，违规则整条输出作废。输出侧：敏感属性词表命中即拦截并告警，记录拦截日志。

5.3 留痕设计（可重建 + 最小化）

留痕字段（f45）：批次、导师身份、岗位任务与企业反馈实例的版本、建议内容、人工修正、签核人。不记录：口令、非必要个人信息。日志采用追加写 + 不可篡改（哈希链）；日志本身也受权限矩阵约束——"谁能看日志、看到什么粒度"【待核实】，默认仅教务与教学质量负责人可见。

5.4 留存与删除

评价记录试点期暂留 90 天，到期由教学质量负责人确认删除或归档（f43）。技术上：每条记录带 retention_until，到期进"待处置"清单，不自动删除，需人工确认；真实组织留存期限【待核实】，不得把试点口径写成制度配置。

六、人工闸门的技术实现

五个闸门在系统里不只是提示框，而是状态机中的必经状态——跳过即流程不合法。

闸门触发条件系统行为通过后方可
G1 要素齐备抽取完成不齐备则退回并附缺失字段进入建议起草
G2 异常 / 争议换岗、无实例、口径不一致、依据缺失、系统不可用停自动建议，写入停止原因 / 接手人 / 人工确认时间三字段，缺一不放行继续流转
G3 教务核对G2 命中的疑点未确认结果不得覆盖原记录覆盖或标记为已核对
G4 口径裁定评分口径争议记录规则使用版本，交教学质量负责人生效新版本
G5 导师定性 + 专业组落课建议成稿定性字段仅导师可写；30 条中 ≥24 条对得上课程才可签核课程动作下发

技术要点：三字段为数据库非空约束，不是前端校验——防止绕过界面直接改状态。

十、待确认事项

以下 6 项直接影响技术方案落地方式，访谈中明确未核实，本方案不代替业务决策：

（1）"可执行"由谁判定、按岗位任务还是课程模块口径；（2）三平台具体系统、版本、部署方式与导出频率；（3）权限分级与日志可见粒度的系统实现上限；（4）异常换岗由谁发起、超时协调时限；（5）90 天到期后的归档保管责任；（6）学生申诉入口、受理人与答复时限（现状流程中结构性缺失）。
