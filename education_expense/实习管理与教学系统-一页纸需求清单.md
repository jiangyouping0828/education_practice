# 实习管理与教学系统 · 一页纸需求清单 v1

**定位一句话**：校企合作场景下，覆盖"实习过程管理 → 教学评价 → 成绩挂钩"全闭环的系统；全校规模、混合部署、AI 辅助整理但不判定。
**依据**：10 项关键决策（1C 过程+评价闭环 / 2B 校企双组织 / 3 移动+Web 并重 / 4 挂钩成绩 / 5B AI 辅助 / 6 混合部署 / 7 全校 / 8 全新开发 / 9 高频复杂换岗 / 10 量化验收）

---

## 一、架构基调（由决策直接推导）

| 决策 | 架构结论 |
| --- | --- |
| 1C + 9 高频换岗 | **统一业务主键 + 事件模型是地基**：「学生×批次×岗位×导师×时间段」做版本化关联（一等公民），评价、反馈、成绩全部挂在此键上——换岗即重算关联，杜绝"反馈发给旧导师" |
| 2B 校企合作 | **双租户数据隔离**：企业侧与学校侧分租户，学生个体评价默认企业间不可见；数据归属规则（评价数据归校、任务数据归企）一期就写进权限模型 |
| 3 双端 | **一套 API、两套界面**：现场端移动优先（弱网离线可用），管理端 Web 优先（批量操作） |
| 4 挂钩成绩 | **签核链 + 不可篡改留痕（哈希链）**：评价改成绩必须经导师签核；成绩字段对 AI 与业务侧只读 |
| 5B AI 辅助 | AI 只做**抽取、归并、起草**三件事，输出必须挂原记录，人工确认后才生效；模型网关统一计量 |
| 6 混合部署 | **数据分级**：学生个人评价/签核数据私有化；统计聚合与模型推理可用云；两端之间只同步去标识化数据 |
| 7 全校 | **模块化单体**（不是微服务）：6 个模块边界清晰（批次岗位、反馈采集、评价签核、AI 服务、报表看板、系统管理），为未来拆分留缝 |
| 8 全新开发 | 无存量包袱，事件模型与主键一次设计到位；预留标准导出接口应对未来集成 |

## 二、用户与角色

| 角色 | 核心操作 | 终端 |
| --- | --- | --- |
| 企业员工（现场导师） | 双周提交任务例子+行为实例、确认交接 | 移动端（弱网可用） |
| 企业管理员 | 岗位发布、导师分派、交接验收 | Web |
| 学校指导教师 | 回访复核、确认 AI 草稿、异常提报 | 移动 + Web |
| 教务管理员 | 汇总、核对疑点、修复队列、映射维护 | Web |
| 专业组 / 教学质量负责人 | 落课评审签核、口径裁定、到期处置 | Web |
| 系统管理员 | 租户、权限矩阵、规则版本 | Web |

## 三、功能范围（MoSCoW）

- **Must（一期必须有）**：实习批次与岗位分配（版本化）；双周反馈提交（移动端离线暂存+待补状态+最后同步时间）；评价与签核链（挂成绩）；AI 评语结构化 + 建议起草（人工确认）；换岗/延期异常处理（即时重算导师关联）；成绩只读对接；双租户权限与数据隔离；指标看板（口径字段可配置）
- **Should（一期尽量有）**：微信/Excel/邮件材料归并（业务编号主键）；人工修复队列（缺关键字段不猜值）；每周复盘与规则版本管理（复测通过才生效）
- **Could（二期）**：岗位任务—课程能力对照表；学生申诉入口；消息提醒中心
- **Won't（明确不做）**：AI 自动评分或给学生定性；成绩写回；对外 SaaS 平台化

## 四、非功能需求（硬约束）

弱网离线可用、记录不丢且不假完成 ｜ 留痕可重建（批次/导师/版本/修正/签核人）且不含口令与非必要个人信息 ｜ 评价记录留存默认 90 天、到期人工确认删除或归档 ｜ 学生个体评价跨企业不可见 ｜ 能力推断必须有行为实例，敏感属性（家庭背景/性别）三层阻断 ｜ 越权访问 0 容忍

## 五、验收指标（一期签字口径）

| 指标 | 目标 | 统计口径 |
| --- | --- | --- |
| 反馈完整率 | ≥85%（基线自定，试点前实测） | 分母/周期/排除规则由业务负责人固定，冻结后不得中途修改 |
| 建议可执行率 | 每批 30 条中 ≥24 条可对应课程/任务/负责人 | 专业组评审判定 |
| AI 兜底召回 | 四类异常（换岗/无实例/口径不一致/依据缺失）100% 拦截转人工 | 评测集全量通过 |
| 教师整理工时 | 较基线可观测下降 | 并行观测项 |
| 越权访问 | 0 次 | 审计日志 |

## 六、风险提示（开工前必须解决）

1. 主键与事件模型设计评审通过后才允许写业务代码（返工成本最高的部分）；
2. 数据归属与隔离规则需校企双方书面确认；
3. 量化指标的基线值（如完整率现状）需在试点前实测冻结，否则验收无锚点。
